# 焼き鳥 とりまる メニュー・オーダーシステム

## 概要

「焼き鳥 とりまる」の、お客さんが自分で使う注文用ウェブアプリです。ブラウザで `index.html` を開くだけで動き、インストールは何もいりません。

開くと「いらっしゃいませ」の画面と人数の入力が出て、そのあとは画面上のタブで「お客さま情報」「メニュー」「カート」「注文済み・会計」の4ページを切り替えて使います。

- **メニュー**：45品をカテゴリのタブで切り替えて見られます。料理ごとにイラストとアレルギー（絵文字と文字）を表示し、アレルギーでの絞り込みや、ひらがな・カタカナを気にしないあいまい検索もできます。人気ランキングもここに出ます。
- **注文**：数量やトッピングを選んで「カートに入れる」、カートで確かめて「注文する」の2段階です。注文したあとも、会計前なら数量の変更や取消ができます。お酒は年齢を確かめてから注文します。
- **おすすめ**：年齢・性別・お腹の空き具合・好み・苦手な食材を入れると、ルールで選んだ「あなたへのおすすめ」と、注文データから選んだ「同じ年代・性別のお客さんに人気」の料理を出します。
- **ハッピーアワー・飲み放題**：17:00〜19:00 はお酒が100円引きです。飲み放題（通常／プレミアム／ソフトドリンク、90分／120分）を申し込むと、残り時間を表示し、対象のドリンクが0円になります。
- **会計**：確認画面を出してから、小計・割引・飲み放題・お通し代・消費税・税込合計・1人あたりの金額を表示します。会計すると画面は次のお客さん用に戻ります。
- **記録**：注文・取消・会計はブラウザの中（localStorage）に記録され、「注文履歴」ボタンでいつでも見られます。
- **広告**：店名の下に、人気No.1・ハッピーアワー・飲み放題・おすすめの広告が5秒ごとにスライドします。

時間で変わる機能は、画面の一番下の「確認用の機能」で時刻を指定したり早送りしたりして、いつでも確かめられます。

## 起動方法

必要なものは Git と Google Chrome だけです。サーバーやライブラリのインストールは不要です。

1. ターミナル（Windows は PowerShell）で次を実行します。

```
git clone https://github.com/kdt26aie40003-oss/restaurantnoyatu.git
cd restaurantnoyatu

# Windows の場合
start index.html

# Mac の場合
open index.html
```

2. コマンドで開けない場合は、フォルダの中の `index.html` を Google Chrome にドラッグ＆ドロップして開きます。
3. 画面上部に「焼き鳥 とりまる」と表示されれば起動成功です。

### 動作環境

| 項目 | 内容 |
|---|---|
| ブラウザ | Google Chrome 最新版で確認（Edge でも動く想定） |
| OS | Windows / Mac どちらでも可 |
| ネット接続 | 不要（外部のファイルを読み込まない） |

### 注文データの確かめ方

画面下の「注文履歴」ボタンを押すと、記録された注文が一覧で表示されます。データはブラウザの localStorage に `torimaru-slips` という名前で保存されています。履歴を消したいときは、注文履歴画面の「履歴をすべて消す」ボタンを押します。

## 確認用の機能

時間で変わる機能を、いつでも確かめられるようにするための機能です。メニュー画面の一番下（「注文履歴」ボタンの下）にあります。

### 時刻を指定する

「確認用：時刻を指定する」にチェックを入れると、時刻の入力欄に入れた時刻を「今の時刻」として使います（日付は今日のまま）。チェックを外すと本当の時刻に戻ります。時刻が空欄やおかしな値のときは「時刻を正しく入力してください」と出して、本当の時刻を使います。

例：時刻を 17:30 にするとハッピーアワーが始まり、画面上部に「ハッピーアワー開催中！ 19:00まで（あと90分）」と出て、お酒が100円引きになります。19:00 にすると終わります。

### 時間を進める（早送り）

「確認用：10分進める」「確認用：30分進める」を押すと、押した分だけ先の時刻を「今の時刻」として使います（何分進めているかを下に表示します）。「時間を元に戻す」で0分に戻ります。「時刻を指定する」と一緒に使えます（指定した時刻から、さらに進めた時刻になります）。進めた分は保存しないので、ページを再読み込みすると0分に戻ります。

例：飲み放題（90分）を申し込んだあと「30分進める」を2回押すと、残り30分になり「ラストオーダーの時間を過ぎました」と出ます。もう1回押すと「飲み放題は終了しました」と出ます。

### 使用した技術

HTML / CSS / JavaScript のみ。外部ライブラリやフレームワークは使っていません。データの保存にはブラウザの localStorage を使います。

## データ設計

### 保存方法

注文データはブラウザの localStorage に、キー名 `torimaru-slips` で JSON 形式の文字列として保存します。

そう決めた理由は、サーバーやデータベースを用意しなくても、ページを閉じたり再読み込みしたりしてもデータが残るからです。起動が「index.html を開くだけ」で済むので、講師の環境でも確実に動かせます。

localStorage の読み書きは try / catch で囲み、失敗してもエラーメッセージを出すだけで画面は止めません。

### データの形

1回の来店（1組のお客さん）を「伝票」として扱います。伝票の中に注文が入り、会計すると会計情報が入ります。

| データ | 項目 |
|---|---|
| メニュー（menu.js） | id（番号）、name（料理名）、price（税抜価格・円）、category（前菜／焼き鳥／一品料理／ドリンク／デザート）、allergens（アレルギー物質の配列）、isAlcohol（お酒かどうか）、dislikeTags（苦手な食材の配列：ねぎ／内臓／魚介／トマト／わさび／梅）、yomi（ひらがなのよみ。検索用）、keywords（関係する言葉の配列。検索用。例：鶏の唐揚げ → 鶏、揚げ物、こってり、からあげ）、toppings（トッピングの配列。ない料理は空）、nomihodai（ドリンクだけ。"通常" か "プレミアム"。日本酒・コカレロ・チャミスル・クライナーは "プレミアム"）、image（イラストの場所。images/menu/料理のid.svg） |
| トッピング（menu.js） | id、name（名前）、price（税抜の追加料金）、allergens（アレルギー物質の配列） |
| 伝票 | slipId（伝票番号）、startedAt（来店日時）、people（テーブルの人数。入力前は null）、customer（お客さんの年代 ageGroup と性別 gender。「おすすめを見る」を押す前は null）、cart（カートの配列）、nomihodai（飲み放題の申し込み。申し込みがなければ null）、orders（注文の配列）、checkout（会計情報。会計前は null） |
| 飲み放題 | course（90 か 120）、plan（通常／プレミアム）、people（人数）、minors（そのうち20歳未満の人数）、startedAt（申し込んだ時刻）、lastOrderAt（ラストオーダーの時刻）、endsAt（終わりの時刻）、adultPrice（大人1人の料金）、minorPrice（20歳未満1人の料金）、total（飲み放題の料金の合計）。時刻は計算しやすいようにミリ秒の数で記録する |
| カート | cartId（カートの番号）、menuId、name、price、toppings、unitPrice、quantity（注文と同じ形。注文日時と状態はない） |
| 注文 | orderId（注文番号）、menuId、name、price（料理の値段）、toppings（選んだトッピングの id・name・price の配列）、unitPrice（料理＋トッピングの1個あたりの値段。飲み放題で頼んだドリンクは0）、nomihodai（飲み放題で頼んだドリンクなら true）、hhDiscount（ハッピーアワー割引の1個あたりの額。開催中に注文したお酒は100、それ以外は0）、quantity（数量）、orderedAt（注文日時）、status（「注文済み」または「取消」） |
| 会計情報 | people（人数）、orderSubtotal（料理・ドリンクの合計）、nomihodai（飲み放題の申し込みの写し。なければ null）、subtotal（小計：料理・ドリンク＋飲み放題の料金）、hhDiscount（ハッピーアワー割引の合計）、otoshi（お通し代）、tax（消費税）、total（税込合計）、perPerson（1人あたり）、paidAt（会計日時） |

取り消した注文はデータから消さず、status を「取消」にして残します。どの注文が取り消されたかも記録として確かめられるようにするためです。

トッピングを追加する前に記録した古い注文には toppings と unitPrice がありません。そのときは toppings を空、unitPrice を price として扱います。hhDiscount がない古い注文や会計情報は、割引0円として扱います。nomihodai がない古い伝票は、飲み放題の申し込みなしとして扱います。

日時（来店・注文・会計）は、すべて getNow() という関数から取ります。確認用の「時刻を指定する」を使うと、この関数が指定した時刻を返します。

## 画面と機能

### 画面構成

開くと最初に、画面いっぱいの「ようこそ画面」で店名「焼き鳥 とりまる」と「いらっしゃいませ！」を大きく表示します。画面をタップするか、3秒たつと「人数入力画面」に切り替わります。

人数入力画面では「何名さまですか？」と聞き、1〜6人のボタンか、入力欄（1〜20の整数）でテーブルの人数を決めます。決めるとメニュー画面に移ります。人数は伝票に保存するので、再読み込みしても入れ直す必要はありません。

メニュー画面は、店名のヘッダーのすぐ下に横幅いっぱいの**広告スライド**（下の「広告スライド」）、その下に**4つのページを切り替えるタブ**を置き、1度に1ページだけ表示します。タブはスクロールしても画面の上に固定されます。人数を決めた直後と会計のあとは「① お客さま情報」のページから始まります。

| ページ | 置くもの |
|---|---|
| ① お客さま情報 | 年齢の入力欄、性別（男性／女性／その他／答えない）、お腹の空き具合（ぺこぺこ／ふつう／少しだけ）、好み（さっぱり／こってり／甘いもの。複数選べる）、苦手な食材（複数選べる）、「おすすめを見る」ボタン、おすすめ結果（「あなたへのおすすめ」と「同じ年代・性別のお客さんに人気」）、「メニューを見る ▶」ボタン |
| ② メニュー | 「飲み放題を申し込む」ボタン（下の「飲み放題」）、人気ランキング（下の「人気ランキング」）、検索欄（下の「検索」）、アレルギーで絞り込み（見出しを押すと開く。下の「アレルギー表示と絞り込み」）、カテゴリタブ（前菜／焼き鳥／一品料理／ドリンク／デザート）、アレルギーで隠した数、料理のカード |
| ③ カート（タブに数量の合計を表示） | カートに入れた料理（トッピング）・数量・金額、行ごとの「−」「＋」「削除」、カートの合計、「メニューに戻る」と「注文する」ボタン |
| ④ 注文済み・会計 | 注文した料理（トッピング）・数量・金額、行ごとの「−」「＋」「取消」、小計（税抜）、「注文まとめ」ボタン、人数の表示と「人数を変える」、「会計する」ボタン |

料理のカードには、左に料理のイラスト、右に料理名、そのすぐ下にアレルギー表示（「🥚卵 🌾小麦」のように絵文字と文字。ないときは「アレルギー表示対象なし」）、税抜価格、トッピングのチェックボックス（ある料理だけ）、数量の入力欄（初期値1）、「カートに入れる」ボタン、「（料理の価格＋トッピング）× 数量」の金額を置きます。

どのページでも、入力ミスのときは赤い文字でその欄のすぐ下に理由を出します。ページの一番下には店側が使う「注文履歴」ボタンと、「確認用の機能」（時刻の指定）を置きます。ハッピーアワー開催中は、ページのタブのすぐ下に黄色い帯で「ハッピーアワー開催中！ 19:00まで（あと○分）」を出します。飲み放題を申し込んだあとは、その下に青い帯で「飲み放題（通常・90分）残り 1:23:45」を出します。カートに入れたときや注文したときは、画面の下に「○○を2個カートに入れました」などのお知らせを数秒だけ出します。

### スマホ対応

画面幅600px以下のときだけ、次のように見た目を変えます。パソコンでは今までのレイアウトのままです。

- ヘッダーを小さくし（「いらっしゃいませ！」の一言は隠す）、ページのタブ4つが1行に収まるように文字を小さめにする。
- メニューカードとおすすめのカードを1列に並べる。
- カテゴリタブは折り返さず、横にスクロールできるようにする。
- お客さま情報の選択肢は、見出しの下に並べる。
- ボタンと入力欄は高さ44px以上、文字は16px以上にして、指で押しやすくする。
- 画面下に「カート ○品・○円 ▶ カートを見る」の固定バーを出し、押すとカートのページに移る。○品はカートの数量の合計。

### アレルギー表示と絞り込み

各料理のカードの、料理名のすぐ下にアレルギーを「🥚卵 🌾小麦」のように表示します。絵文字だけだと伝わらない人がいるので、文字も必ず一緒に出します。

| 品目 | えび | かに | くるみ | 小麦 | そば | 卵 | 乳 | 落花生 |
|---|---|---|---|---|---|---|---|---|
| 絵文字 | 🦐 | 🦀 | 🌰 | 🌾 | 🍜 | 🥚 | 🥛 | 🥜 |

メニューの上の「アレルギーで絞り込み」の見出しを押すと、8品目のチェックボックスが開きます。閉じていても、チェックしている数を見出しに「（2つ選択中）」のように出します。チェックしたものを1つでも含む料理を一覧から隠します。隠した数は「○品を非表示にしています」と出し、「すべて解除」で元に戻せます。カテゴリタブや検索と組み合わせても使えます。おすすめ機能でも、チェックしたアレルギーを含む料理は「選べない料理」として出しません。

### 検索

メニューの上の検索欄に1文字打つごとに、結果を表示し直します。

1. 入力と料理のデータの両方を同じ形にそろえてから比べる：カタカナ → ひらがな、全角英数字 → 半角、大文字 → 小文字、前後の空白を消す。
2. 入力をスペース（全角・半角どちらも）で区切り、どれか1つの言葉が「料理名・よみ・キーワード・カテゴリ名」のどこかに一部でも含まれていれば表示する。全部の言葉が合わなくても出る。
3. 検索欄に文字があるときは、選んでいるタブに関係なく全カテゴリから探し、各料理にカテゴリ名を表示する。検索欄を空にするか、タブを押すと、タブの表示に戻る。
4. 1件もないときは「見つかりませんでした。別の言葉で探してみてください」と出す。

### カート・注文と取り消し

注文は「カートに入れる」→「注文する」の2段階です。

1. メニューやおすすめの「カートに入れる」を押すと、数量のチェックとお酒の年齢確認をしてから、カートに入れます。同じ料理・同じトッピングがもうカートにあれば、数量を足します（合わせて10個まで）。この時点では、まだお店には届いていません。
2. カートのページでは「−」「＋」で数量を変えたり、「削除」で外したりできます。カートの中身も伝票と一緒に localStorage に保存するので、再読み込みしても消えません。
3. 「注文する」を押すと、お酒の年齢確認をもう一度してから、カートの中身をすべて注文として記録し、カートを空にして「④ 注文済み・会計」のページに移ります。カートが空のときは「カートが空です。メニューから料理を選んでください」と出します。

注文したものは、会計前なら「−」「＋」で数量を変えたり、「取消」で取り消したりできます。カートに注文していない料理が残っているときは、「会計する」を押しても「カートにまだ注文していない料理があります…」と出して会計しません。

「会計する」を押すと、その伝票に会計情報を記録して保存し、すぐに新しい伝票を始めます。会計の結果の窓を閉じると、ようこそ画面に戻ります。画面の注文一覧は空になりますが、会計した伝票のデータは localStorage に残り、店側は「注文履歴」で確かめられます。会計済みの伝票は画面に出ないので、会計後に注文や取消はできません。

お酒（isAlcohol が true の料理）を注文するときは、お客さま情報の年齢を確かめます。年齢が入っていなければ「お酒の注文には、先に年齢を入力してください」、20歳未満なら「20歳未満の方はお酒を注文できません」と表示し、注文しません。お酒のカードには「お酒（20歳以上）」の印を付けます。会計すると、次のお客さんのために年齢の入力欄を空に戻します。

localStorage の全部の伝票から、同じ年代・同じ性別の伝票を集め、取り消していない注文の数量を料理ごとに合計して、多い順に上位3品を出します（同じ数なら id の小さい順。選べない料理は飛ばす）。見出しは「20代・女性のお客さんに人気」のようにします。性別が「答えない」のときは同じ年代だけで集計し、見出しを「20代のお客さんに人気」にします。

当てはまる料理がまだ3品ないときは、「まだデータが少ないので、お店全体の人気を表示します」と出して、全部の伝票のランキングから出します。customer がない伝票は、年代・性別の集計には使いません。

### 会計

「会計する」を押すと、人数と注文0件のチェックをしてから、画面の上に「お会計の確認」の窓を出します。窓には注文内容（料理名・トッピング・数量・金額）と、下の計算の内訳を出し、「会計すると注文の変更や取消はできません」と注意書きを入れます。「戻る」を押すと何も変えずに閉じ、「この内容で会計する」を押すと会計を確定します。

金額は次の順に計算します。

1. 小計：取り消していない注文の「1個あたりの値段（料理＋トッピング）× 数量」の合計。飲み放題を申し込んだ伝票は、これに飲み放題の料金を足す（内訳に「料理・ドリンク」「飲み放題（通常・90分）大人 ○人 × ○円」「ソフトドリンク飲み放題 ○人 × ○円」の行を出す）。
2. ハッピーアワー割引：取り消していない注文の「hhDiscount × 数量」の合計（ある会計だけ内訳に「ハッピーアワー割引 −○円」の行を出す）。
3. お通し代：1人300円 × 人数。
4. 消費税：（小計 − ハッピーアワー割引 ＋ お通し代）× 10%。1円未満は切り捨て。
5. 税込合計：小計 − ハッピーアワー割引 ＋ お通し代 ＋ 消費税。
6. 1人あたり：税込合計 ÷ 人数。1円未満は切り上げ。

例：小計2,000円・2人 → お通し代600円 → 消費税260円 → 税込合計2,860円 → 1人あたり1,430円。

### ハッピーアワー

毎日 17:00〜19:00 に開催します（19:00 ちょうどで終わり）。開催中は、お酒（isAlcohol が true の料理）が1杯100円引きです。トッピングは割引しません。

- 開催中は、ページのタブの下に「ハッピーアワー開催中！ 19:00まで（あと○分）」を出し、1分ごとに更新します。開催中でないときは出しません。
- 開催中は、お酒のカードに元の値段を取り消し線で出し、その横に割引後の値段を赤字で出します。カートでも、今の割引を引いた金額を出します。
- 割引は「注文した時刻」（カートの「注文する」を押した時刻）で決めます。そのとき開催中なら、注文に hhDiscount: 100 を記録します。あとで時間が過ぎても、数量を変えても、1杯あたりの割引は変わりません。
- 注文済みのページでは、割引のある注文に「ハッピーアワー −○円」の印を付け、小計の下に割引の合計を出します。注文まとめと会計（確認画面も含む）の内訳にも「ハッピーアワー割引 −○円」を出し、消費税は割引したあとの金額にかけます。
- おすすめで選ばれたお酒にも、開催中は「ハッピーアワーで100円引き」と出します。
- 時刻はすべて getNow() から取るので、「確認用の機能」で時刻を指定すれば昼でも試せます。

### 飲み放題

#### プランと料金（1人あたり・税抜）

| プラン | 90分 | 120分 | 飲み放題になるドリンク |
|---|---|---|---|
| 通常 | 1,500円 | 2,000円 | 日本酒・コカレロ・チャミスル・クライナー以外のドリンク |
| プレミアム | 2,000円 | 2,500円 | すべてのドリンク |
| ソフトドリンク（20歳未満の人） | 800円 | 1,000円 | お酒以外のドリンク |

#### 申し込み

メニューのページの「🍻 飲み放題を申し込む」を押すと、申し込みの窓を出します。時間（90分／120分）、プラン（通常／プレミアム）、人数（1〜20の整数。最初はテーブルの人数）、そのうち20歳未満の人数（0〜人数の整数）を入れると、「大人2人×1,500円（通常）＋20歳未満1人×800円（ソフトドリンク）＝3,800円（税抜）」のように料金を出します。

- テーブル全員が同じ時間・同じプランに入ります。20歳以上の人は選んだプラン、20歳未満の人は自動でソフトドリンク飲み放題になります。全員20歳未満のときは、プランを選べなくします。
- 入力がおかしいときはエラーを出して「申し込む」を押せなくします。「申し込み後は取り消せません」と注意書きを入れ、「申し込む」で確定、「戻る」で何も変えずに閉じます。
- 会計前ならいつでも（途中からでも）申し込めます。1つの伝票で申し込めるのは1回だけで、申し込んだあとはボタンを「申し込み済み」にして押せなくします。会計すると新しい伝票になるので、会計後の伝票には申し込めません。
- 申し込む前に頼んだドリンクは、通常料金のまま変えません。

#### 時間の管理

- 残り時間は申し込んだ時刻から数えます。ラストオーダーは終了の30分前です。時刻はすべて getNow() から取ります。
- 申し込み後は、画面上部に「飲み放題（通常・90分）残り 1:23:45」を出し、1秒ごとに更新します。ラストオーダー以降は「ラストオーダーの時間を過ぎました」を足し、終了時刻になったら「飲み放題は終了しました」と出します。
- 申し込みの内容は伝票に保存するので、ページを再読み込みしても続きます。

#### 注文のときの扱い

- ラストオーダーまでのあいだに、プランの対象のドリンクを「注文する」と、値段を0円にして注文に nomihodai: true を記録し、注文済みに「飲み放題」の印を付けます。メニューのカードとカートでも、対象のドリンクは「飲み放題 0円」と出します。
- ソフトドリンクはどのプランでも対象です。お酒は、大人のプランの対象なら対象です（通常プランのときの日本酒などは対象外で、通常料金）。ラストオーダー以降は、どのドリンクも通常料金です。
- 1回の「注文する」で頼める飲み放題のドリンクは人数分まで、そのうちお酒は20歳以上の人数分までです。超えたら「飲み放題のお酒は、1回の注文で2杯（20歳以上の人数分）までです」のように出して注文しません。人数分の決まりを守るため、注文済みの飲み放題のドリンクは「＋」で増やせません（「−」と「取消」はできます）。
- お酒の年齢確認は今までどおり行います。
- 飲み放題で0円のドリンクにはハッピーアワー割引をかけません。対象外のドリンクには、開催中ならハッピーアワー割引をかけます。

#### 会計

- 飲み放題を申し込むと、会計の人数を飲み放題の人数にそろえ、「人数を変える」を押せなくします。
- 飲み放題の料金は小計に足し、お通し代と一緒に消費税をかけます。注文済みのページの小計の下にも、飲み放題の料金を出します。
- おすすめでは、飲み放題の時間内は対象のドリンクを先に選び、「飲み放題対象」と出します。

### 人気ランキング

メニューのページの上に「人気ランキング」を置きます。

- localStorage に記録された全部の伝票から、取消を除いた注文の数量を料理ごとに合計します。トッピングの違いは区別せず、飲み放題の0円のドリンクも数に入れます。
- 多い順に上位3品を「🥇 1位 つくね（タレ・1本）（12個）」のように出します。同じ数のときは id の小さい料理を上にします。
- 各料理に「カートに入れる」ボタンを付け、その場でカートに入れられます（数量1・トッピングなし。お酒は年齢確認をします）。
- 注文・取消・数量変更をしたら、すぐにランキングを表示し直します。
- 注文が1件もないときは「まだ注文がありません」と出します。

### 広告スライド

店名のすぐ下に、横幅いっぱいの広告を出します。広告は次の4枚です。

| 順番 | 広告 | 中身 | 押すと移る場所 |
|---|---|---|---|
| 1 | 人気No.1 | 「人気No.1は○○！」（ランキング1位の料理。まだ注文がなければ「名物 つくね、ぜひどうぞ！」） | メニューのページの人気ランキング |
| 2 | ハッピーアワー | 開催中なら「ハッピーアワー開催中！ お酒100円引き 19:00まで」、それ以外は「毎日17:00〜19:00はお酒が100円引き」 | メニューのページのドリンクのタブ |
| 3 | 飲み放題 | 「飲み放題 90分1,500円から。プレミアムなら全ドリンクOK」 | メニューのページの「飲み放題を申し込む」ボタン |
| 4 | おすすめ | 「年齢と気分を入れると、おすすめが見られます」 | お客さま情報のページのおすすめ欄 |

- 下に●を4つ並べて今何枚目かを示し、●を押すとその広告に切り替えます（そこから5秒を数え直します）。
- 広告の中身は切り替わるたびに最新にします（ランキング1位と、getNow() で見たハッピーアワーの開催状況）。
- 長い文字は折り返して、スマホでも横幅に収めます。
- 各広告の左には、内容に合ったイラスト（トロフィー、ビールと時計、乾杯、おすすめのメモと星）を出します。

### イラスト

料理45品と広告4枚には、それぞれイラストを付けています。料理のイラストは、メニューのカード・おすすめのカード・人気ランキングに出します。

- イラストはすべて SVG（図形を文字で書いた画像のファイル）で、このシステムのために作ったものです。写真やネット上の素材は使っていないので、著作権の心配がなく、ネットにつながっていなくても表示できます。
- 背景の色はカテゴリごとに変えています（前菜は緑、焼き鳥はうすい茶、一品料理は黄色、ドリンクは水色、デザートはピンク）。
- 料理名は文字でも出しているので、イラストの alt（画像の説明）は空にして、読み上げソフトで料理名が2回読まれないようにしています。

### 注文済みの数量変更

「④ 注文済み・会計」のページの各行の「−」「＋」で数量を1〜10の範囲で変えられます。1のときは「−」、10のときは「＋」を押せません。注文を消したいときは「取消」を使います。変更するとすぐ localStorage に保存します。会計すると画面がリセットされるので、会計後は変えられません。

### 注文まとめ

「注文まとめ」ボタンで、今の伝票の注文を取消を除いて「料理」と「ドリンク」に分けて表示します。同じ料理で同じトッピングのものは1行にまとめて、品名・トッピング・合計数量・金額を出し、最後に合計の品数と小計を出します。会計前は「④ 注文済み・会計」のページのボタンから、会計後は会計の結果の窓の「注文まとめ」ボタンから見られます。

### 入力チェック

入力値はすべて、全角数字を半角に直してから Number で数値に変え、Number.isInteger で整数かどうかを確かめます。どんな値が入っても、エラーで停止しないようにします。

| 入力欄 | 受け付ける値 | エラーにする例 | エラーメッセージ |
|---|---|---|---|
| 年齢 | 0〜120の整数 | 空欄、abc、-5、20.5、999 | 年齢は0〜120の整数で入力してください |
| 数量 | 1〜10の整数 | 空欄、abc、0、-1、1.5、11 | 数量は1〜10の整数で入力してください |
| 人数 | 1〜20の整数 | 空欄、abc、0、-2、2.5、21 | 人数は1〜20の整数で入力してください |
| 注文一覧 | 1件以上 | 注文が0件で会計 | 注文がありません |

## 自分で決めたこと

| 決めたこと | 理由 |
|---|---|
| ブラウザだけで動く作りにし、保存は localStorage にした | インストール不要で、講師が index.html を開くだけで確実に動かせるため |
| 最初にようこそ画面を出し、タップか3秒でメニュー画面に移るようにした | お店に入ったときのように、まず店名とあいさつで迎えるため。待たずに進みたい人はタップですぐ移れる |
| ルールのおすすめには性別を使わず、実際の注文データから「同じ年代・性別の人がよく頼んだ料理」を出す形にした | 性別で料理を決めつけると偏見につながるため。データで選べば、決めつけではなく実際に頼まれたものを紹介できる |
| 性別は「答えない」を選べるようにし、年齢は年代だけを記録した | 細かい個人情報を残さないようにするため |
| 苦手な食材を選べるようにし、含む料理はおすすめに出さないようにした | 食べられないものをすすめても注文につながらないため |
| 年齢の入力をお酒の年齢確認にも使った | 20歳未満の飲酒は法律で禁止されているため。入力欄を1つにまとめると操作も簡単になる |
| メニューの価格は税抜で表示し、会計で消費税10%を加えた | 店内での飲食は消費税10%のため。居酒屋のメニュー表示に多い形に合わせた |
| 消費税は1円未満切り捨て、割り勘は1円未満切り上げにした | 切り捨てはお客さんに不利にならない。割り勘は切り上げないと合計に足りなくなるため |
| お通し代を1人300円にした | 居酒屋らしさを出すため。人数分を自動で会計に入れる |
| 年齢は0〜120、数量は1〜10、人数は1〜20の整数だけ受け付けた | ありえない値や打ち間違いを防ぐため |
| 全角数字は半角に直して受け付けた | 日本語入力のまま数字を打っても使えるようにするため |
| 取り消した注文は消さずに「取消」として残した | 何を注文して何を取り消したかを記録として確かめられるようにするため |
| 人数は会計のときではなく、最初の人数入力画面で聞くようにした | お店で席に案内されるときに人数を聞かれるのと同じ流れにするため。最初に決めておけば、会計のときに入れ忘れることもない。間違えたときのために「人数を変える」ボタンも付けた |
| 会計したら画面をリセットして新しい伝票を始め、ようこそ画面に戻るようにした | 1台の端末を次のお客さんがそのまま使えるようにするため。会計済みの伝票は画面から外れるので、要件の「会計前であれば取り消せる」どおり会計後は変更できず、データは店側に残る |
| アレルギーは特定原材料8品目を表示した | 食品表示で表示が義務づけられている品目のため |
| アレルギーは絵文字と文字を必ず一緒に出した | 絵文字だけだと意味が伝わらない人がいるため |
| アレルギーの絞り込みは「チェックしたものを含む料理を隠す」形にした | アレルギーのある人が、食べられない料理をうっかり注文しないようにするため。隠した数を出すので、隠れていることにも気づける |
| 検索は、言葉のどれか1つが合えば出す形にした | 「ビール あまい」のように思いついた言葉を並べても、何かしら候補が出るようにするため |
| 検索の前に、カタカナ・全角・大文字の違いをそろえた | 「カラアゲ」「からあげ」のように打ち方が違っても同じ結果になるようにするため |
| スマホのときだけ見た目を変え、パソコンでは今までのままにした | お客さんは自分のスマホで注文することが多いが、パソコンで確かめる講師の画面は崩したくないため |
| スマホの固定バーの「○品」は数量の合計にした | 「もも × 3」なら3品と数えた方が、頼んだ量の感覚に合うため |
| 画面を4つのページに分け、上のタブで切り替えるようにした | 1ページに全部並べると縦に長くなり、何を注文したか見るのにスクロールが必要だったため。前菜・焼き鳥のタブと同じ操作で切り替えられる |
| 「カートに入れる」と「注文する」の2段階にした | 選んだものをまとめて確かめてから注文できるようにするため。カートの段階ではまだ記録に残さず、「注文する」で初めて注文として記録する |
| 「注文する」のときにもお酒の年齢確認をもう一度した | カートに入れたあとで年齢を書き換えても、20歳未満がお酒を注文できないようにするため |
| カートに料理が残っているときは会計できないようにした | 頼んだつもりの料理が注文されないまま会計してしまうのを防ぐため |
| ハッピーアワーの割引は、注文した時刻で決めて注文に記録した | 19:00 をまたいで会計しても、開催中に頼んだお酒は割引のままにするため。会計のときの時刻で決めると、頼んだときの約束と金額が変わってしまう |
| ハッピーアワーの割引は、小計から引いたあとに消費税をかけた | 値引きは値引き後の金額に税をかけるのが普通で、お客さんに不利にならないため |
| 今の時刻はすべて getNow() から取り、確認用に時刻を指定できるようにした | 講師が昼に確認してもハッピーアワーを試せるようにするため。時刻を取る場所を1つにまとめると、指定した時刻がどこにでも正しく効く |
| 料理と広告のイラストは、写真ではなく SVG で作った | 著作権の心配がなく、ファイルが軽く、ネット接続なしでも表示できるため。拡大してもぼやけないので、スマホでもパソコンでもきれいに見える |
| メニューのカードはイラストを左、料理名を右に並べた | 縦に積むとカードが長くなり、スクロールが増えるため。パソコンではカードの幅を260px以上にして、料理名が窮屈にならないようにした |
| ランキングはお店全体の全部の伝票から数えた | 「お店で本当によく頼まれている料理」を出すため。年代・性別ごとの人気は、おすすめ機能の方で出している |
| ランキングと広告のボタンは「カートに入れる」にした | ほかの料理と同じく、カートで確かめてから注文する流れにそろえるため |
| 広告は、1枚目の写しを使ってループさせた | 4枚目から1枚目に戻るときに逆向きに流れると不自然なため、いつも同じ向きにスライドするようにした |
| 飲み放題の0円は「注文する」を押した時刻で決めた | カートに入れたあとでラストオーダーを過ぎたら、通常料金になるのが自然なため。ハッピーアワーと同じ考え方にそろえた |
| 注文済みの飲み放題のドリンクは「＋」で増やせないようにした | 「1回の注文は人数分まで」の決まりを、数量変更ですり抜けられないようにするため。追加したいときは、もう一度カートから注文する |
| 飲み放題を申し込んだら「人数を変える」を押せなくした | 飲み放題の料金とお通し代の人数がずれないようにするため |
| 飲み放題だけ申し込んで何も頼んでいなくても会計できるようにした | 飲み放題の料金はかかっているので、0件でも会計が必要になるため |
| 早送りした分は保存しないことにした | 確認用の機能なので、再読み込みで元に戻る方が安全なため。保存先も torimaru-slips だけにそろえたかった |
| アレルギーの絞り込みは、見出しを押すと開くたたみ式にした | メニューのページを短くし、料理がすぐ見えるようにするため。選択中の数は見出しに出すので、閉じていても絞り込み中だとわかる |
| 注文には、そのときのトッピングの名前と値段も一緒に記録した | あとでメニューの値段を変えても、昔の注文の金額が変わらないようにするため |
| 注文するたびに注文済みの行を分け、まとめるのは「注文まとめ」だけにした | いつ何を頼んだかを1件ずつ記録として残しつつ、テーブル全体で何を頼んだかも見やすくするため |
| 数量を0にする代わりに「取消」を使うようにした | 「−」で消してしまう打ち間違いを防ぎ、取消は記録に残すため |
| 会計の前に確認画面を挟んだ | 会計すると変更できなくなるので、押し間違いで会計してしまわないようにするため |

## できていないこと・今後の改善

- 注文データは使ったブラウザの中にしか残らない。別のパソコンやブラウザでは見られない。
- 1台の端末を、お客さんが順番に使う前提で作っている。いくつかのテーブルで同時に別々の端末から注文することはできない（テーブル番号の考え方もない）。
- 店員側の画面（厨房への注文表示など）はない。「注文履歴」はお客さんの画面の一番下にあり、だれでも開ける。
- 確認用の早送りで進めた時間は保存しないので、ページを再読み込みすると0分に戻る（飲み放題の残り時間が増えたように見える）。
- 時刻はその端末の時計を使うので、端末の時計がずれているとハッピーアワーや飲み放題の時間もずれる。
